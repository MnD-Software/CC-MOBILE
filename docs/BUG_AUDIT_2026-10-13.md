# Code bug audit — 13 October 2026

The audit covered the Expo application, its FastAPI backend, authentication,
checkout and recovery, catalogue caching, notifications, and build configuration.
The Expo SDK 57 reference and notification documentation were read before edits:
https://docs.expo.dev/versions/v57.0.0/
https://docs.expo.dev/versions/v57.0.0/sdk/notifications/

## Repairs

| Area | Verified problem and resulting behavior |
| --- | --- |
| Backend authentication | Two sessions could rotate one refresh token. Rotation now claims it atomically and commits the replacement together with revocation. Concurrent duplicate registration returns 409 rather than an uncaught database exception. |
| App authentication | Late secure-storage writes could erase a newer account's token; logout could leave the account visible when storage reads failed; a failed login could discard an ongoing refresh. Credential writes and deletion now run in order, logout clears visible identity immediately, and login waits for the active refresh. |
| API account boundary | A delayed 401 could replay a mutation with the next account's bearer token. Requests retain their original session generation and discard stale responses and retries. |
| Checkout | Concurrent submissions share one payment promise. Cart construction, restoration and payment verify product IDs and quantities, including equal-price substitutions. Wrong currencies, fractional quantities and unsafe integer totals are rejected. |
| Payment recovery | Future-dated records cannot remain valid indefinitely. Unsafe redirects never open, and an order already created remains available through its official receipt. Stale forms cannot open payment or display another account's handoff. Completed shopping settles the purchased configurations rather than clearing unrelated bag contents. |
| Catalogue | Malformed upstream products/images produce recoverable failures instead of crashes. Offline catalogue expiry is enforced in memory and on disk, including future timestamps. |
| Order tracking | Non-object upstream billing data returns 502 without exposing private order details. |
| Notifications | Unsupported URLs cannot resolve inherited object properties. Initial notification responses and listener events navigate once, and callbacks from a departed account cannot clear newer responses. |
| Accessibility | React Native Web omitted legacy accessibility state objects from the DOM. Controls now expose checked, selected, expanded, disabled and busy state through explicit ARIA props while retaining their native state. The real web renderer and browser verify appearance selection, disclosure expansion and shared button state. |
| Expo configuration | Dynamic configuration preserves the EAS iOS extension provisioning metadata in app.json. |
| Verification | Browser checks now match the current homepage, filter sheet and collapsed coupon tools. Existing formatting failures were corrected. |

## Validation

- `npm.cmd test`: **119 passed**, including 17 new app regression tests.
- `python -m pytest tests -q --tb=line` from `backend`: **40 passed**, including 8 new backend regression cases. The initial regression run reproduced all 8 backend failures before repair.
- `npm.cmd run typecheck`: passed.
- `npm.cmd run format:check`: passed.
- Additional formatting and syntax checks for the browser checker and native notification files: passed.
- Preview and production `release:check` with the configured HTTPS mobile API: passed.
- `git diff --check`: passed.
- Expo web export: passed, `artifacts/bug-audit-2026-10-13/export`.
- Android and iOS Hermes exports: passed, `artifacts/bug-audit-2026-10-13/native-bundles`. Both bundles were inspected for the final checkout recovery change.
- Final browser regression: passed, 12 visits across 9 routes, 12 screenshots, and zero unhandled exceptions. Verified live catalogue and budget filtering, appearance selection and persistence, guest coupon save/select/remove, product details, registration view, and empty checkout, at phone and tablet sizes. Evidence: `artifacts/bug-audit-2026-10-13/browser-verified/result.json`.

Browser verification used the checker's public GET transport bridge to model
native catalogue access when the website rejects localhost CORS. It used real
catalogue responses, intercepted no private or payment transport, and submitted
no payment or registration.

Hermes execution and the public website transport required approved execution
outside the sandbox. A direct public Shop catalogue read returned HTTP 200.
The backend suite reports one existing Starlette/httpx deprecation warning.

## Boundaries

These changes are source repairs prepared for GitHub delivery. No backend
deployment, OTA publication, or installable native app build was made. Android device
enumeration found no attached devices. Native installation, notification taps,
secure storage on a physical device, and real payment-provider transactions
remain unverified. Google identity, password-recovery delivery and remote push
registration still require their documented backend/provider implementations.

The checks establish the repaired cases; they do not prove the absence of every
possible bug or replace an end-to-end device release review.
