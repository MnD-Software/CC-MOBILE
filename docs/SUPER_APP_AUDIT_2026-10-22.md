# Cake City platform audit — 22 October 2026

Audit baseline: local `master` at `5d320a1`. Only pre-existing change was an untracked preview APK in `downloads/`; preserve it. No production writes, payments, messages or deployments were performed. Evidence below comes from source and executed checks, not inherited README claims.

## Current architecture and checks

- Expo Router file routes in `app/`; Expo ~57.0.24, React Native 0.86.3, React 19.2.3, TypeScript 6. React Query supplies remote state; Zustand persists the local bag. Shared semantic tokens and platform-specific components already exist.
- FastAPI, SQLAlchemy, PostgreSQL/psycopg in production; SQLite in development. Existing database owns app identities, addresses, celebrations, enquiries, editorial content and a local Club ledger. Redis provides optional shared caching and rate limits.
- Public WooCommerce Store API supplies products and server carts. Authenticated orchestration uses `EXPO_PUBLIC_API_URL`. WooCommerce remains the authority for selling prices, stock, checkout and website payment.
- Reviewed local branches and recent commits; only `master` and `origin/master` are present locally. Remote verification is recorded separately when available.
- `npm test`: **127 passed**. `npm run typecheck`: **passed**. `cd backend; ..\.venv\Scripts\python.exe -m pytest tests -q`: **40 passed**, one Starlette/AnyIO deprecation warning. Running pytest from repository root fails module collection; use backend as the working directory.
- Bare `npm run release:check`: **fails** because the process has no explicit `EXPO_PUBLIC_API_URL`. This is a useful release guard, not evidence that EAS profiles omit the URL.
- `npm audit --json`: **34 findings: 1 critical, 27 high, 6 moderate**, including transitive toolchain dependencies. Raw snapshot: ignored local `artifacts/dependency-audit-2026-10-22.json`. Suggested automatic fixes include Expo/RN downgrades; do not apply blindly. Python dependency scanning and actual native build validation are still outstanding.
- Read-only public product request: **HTTP 200**. Backend `/health` and `/v1/mobile/config`: both exceeded a 25-second timeout. This does not establish whether the service is down or cold-starting. No authenticated live operation was verified.
- Expo v57 reference reviewed before code: https://docs.expo.dev/versions/v57.0.0/. Its React/RN and Node requirements match this package family. This is not a dependency compatibility or device-runtime certification.

## Critical release blockers

1. Source permits default JWT signing secret and direct Uvicorn bypass of the persistent-database launcher check. Redis absence silently removes rate limiting. Fix before production launch.
2. No approved live mobile payment account (owner brief). Existing website Pesapal operation is a separate boundary; no payment was attempted here. Do not replace it with simulated success.
3. Backend reachability and authenticated end-to-end checkout/order state are unverified. Delivery capacity, time slots and production events need operational contracts.
4. Enquest ownership/integration, eTIMS approval and seller details, dispatch interface, identity email/OAuth delivery remain external dependencies.
5. Dependency findings, store accounts/signing, device performance/accessibility, backup restoration and privileged MFA remain release gates.
